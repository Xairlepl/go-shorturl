# 设计说明

这份文档讲「为什么这样写」，具体实现见代码。README 里有功能清单和性能数据。

## 分层

```text
HTTP  ──►  Handler  ──►  Service  ──►  Repository / Cache  ──►  MySQL / Redis
```

- **Handler** 只做协议层的事：绑定参数、校验格式、写响应，不判断业务规则。
- **Service** 承载业务：短码生成、缓存策略、归属校验、统计聚合。
- **Repository** 只做持久化，不掺业务判断。
- **Cache** 是独立封装，出错时返回明确的错误值（`ErrCacheMiss` / `ErrEmptyCached`），由 Service 决定怎么降级。

这样分层不是为了形式整齐，而是为了让「降级」有地方写：缓存出问题时，处理逻辑集中在 Service，不会散落到 Handler 的每个分支里。

## 读路径为什么这样设计

跳转是最高频的操作，一次跳转里每多一次 MySQL 查询，整体容量就少一截。所以：

```text
GET /:code
    │
    ├─ 短码格式校验（不合法直接 404，不触达任何存储）
    │
    ├─ Redis HIT ─────────────────────► 302
    │
    └─ MISS ─► singleflight ─► MySQL ─► 回填缓存 ─► 302
```

三个决定：

**格式校验放在最前面。** 非法短码在这一步就返回，不浪费一次 Redis 往返。压测里的基线（15,474 RPS）走的就是这条路径，它代表框架层能承受的上限。

**未命中交给 singleflight。** 冷门链接被同时访问时，不合并就是 N 次相同查询。合并之后只有一次真正回源，其余请求等待结果。

**查不到也缓存。** 数据库里没有的短码用很短的 TTL（默认 1 分钟）写一个空值标记。否则一个不存在的短码被反复请求，每次都会穿透到 MySQL。

## 写路径为什么把统计拆出去

跳转本身不需要写数据库。如果每次跳转都 `UPDATE visit_count = visit_count + 1`，MySQL 会立刻成为瓶颈，而这个写对用户没有任何价值——用户只关心跳得快不快。

所以拆成两段：

```text
Redirect ──► Redis INCR ──► 返回 302
                 │
                 └─ 每 10 秒批量落库 ──► short_urls.visit_count
```

明细（IP、UA、Referer）同样不在跳转链路里写：先进内存缓冲区，由后台 goroutine 批量写 `url_visits`。缓冲区消费时维护了 `code → url_id` 的内存映射，避免每条明细都查一次库拿 id。

代价是统计变成最终一致：Redis 里的计数和 MySQL 里最多差一个周期。对「访问次数」这种指标，这个误差可以接受。

## 一致性上的取舍

| 操作 | 顺序 | 失败时怎么办 |
|---|---|---|
| 创建 | 写 MySQL → 回填 Redis | 回填失败只记日志，等下次读取时重建 |
| 删除 | 删 MySQL → 删 Redis | 删缓存失败只记日志，靠 TTL 自然过期 |

**不让缓存失败回滚数据库事务**：缓存是加速层，不是事实来源。为了缓存写失败去回滚一笔已经成功的业务写入，是把可靠性问题变得更糟——数据没存进去，缓存倒是干净了。

代价是存在短暂的不一致窗口：删库成功、删缓存失败时，缓存里会留着旧值，直到 TTL 到期。

## 安全上的几个决定

- **密码**：bcrypt（`DefaultCost`）。不自己实现哈希，明文不落库、不进日志。
- **JWT**：Secret 从环境变量读。启动时如果发现还是默认的 `change-me`，日志里告警，避免带着默认密钥上线。
- **开放重定向**：原始 URL 只接受 `http` / `https`。短链服务天然是重定向器，不校验协议就等于给 `javascript:` 和 `data:` 开了门。
- **短码不可预测**：`crypto/rand` 生成 Base62，不用自增 ID 转码。自增转码意味着别人能顺着猜到你所有的短链。
- **归属校验**：`/api/v1/urls/:id` 这类接口除了验 JWT，还要确认这条链接属于当前用户。只验登录不验归属，等于任何登录用户都能删别人的链接。

## 可观测性

已经实现的：

- 每个请求生成 `request_id`，写进响应头，也带进该请求的所有日志
- 结构化日志（`log/slog`）；压测时用 `LOG_LEVEL=warn` 关掉每请求日志，否则测的是 stdout I/O
- `Recovery` 中间件捕获 panic，转成 500 并记录堆栈，不让单个请求带崩进程
- `/healthz` 供外部探活
- 信号驱动的优雅退出：先停新请求，再关后台 worker；flusher 在关闭阶段会补一次落库

没做的：指标暴露（Prometheus）、链路追踪、慢查询日志。这些在单机项目里收益不明显，但真实服务必须有。
